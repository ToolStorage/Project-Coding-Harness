# Project Coding Harness

자연어로 개발하는 사람을 위한 **프로젝트 기억 + 회귀검증 + 적대적 검수** 플러그인입니다. KDI, Unity, 특정 언어나 아키텍처를 요구하지 않습니다. 실제 프로젝트 코드를 먼저 읽고 그 프로젝트의 구조를 따릅니다.

Git으로 공유하는 로컬 플러그인입니다. 공식 스토어, 별도 공개 서버, API 키, Python 외부 패키지는 필요하지 않습니다. 사용 중인 Codex 모델이 분석과 개발을 수행하므로 해당 계정의 사용량은 발생합니다.

## 설치

필수: Python 3.10 이상, Git, 로그인된 Codex CLI. Codex의 로컬 프로젝트 실행 환경을 대상으로 합니다. 웹 ChatGPT에서 Git 링크만 넣는 설치 방식이 아닙니다.

```text
git clone https://github.com/ToolStorage/Project-Coding-Harness.git
cd Project-Coding-Harness
python install.py
```

macOS/Linux에서 `python` 대신 `python3`를 사용해야 할 수 있습니다. 설치 프로그램은 클론의 마켓플레이스와 스킬을 등록하고, 현재 Python 및 스크립트의 절대 경로로 로컬 MCP 서버를 등록합니다. **설치 후 이 폴더를 이동하거나 삭제하지 마세요.** 앱을 재시작하고 작업할 프로젝트에서 새 대화를 여세요. 이 플러그인 저장소 자체에서 개발할 필요는 없습니다.

> Project Coding Harness 설정 화면을 열어줘.

프로젝트명이 표시되면 **프로젝트 분석하기**를 누르세요. 분석은 현재 대화의 AI가 실제 코드를 읽어 수행합니다. 설치만으로 자동 분석하거나 전역 기억을 변경하지 않습니다.

## 사용할 수 있는 것

- 미분석/분석됨/갱신 권장 상태와 프로젝트명·경로 표시.
- 프로젝트 분석 및 명시적 기억 갱신 버튼.
- 기본/심층 검수 깊이와 최대 1~10회 반복 설정. 기본 3회. 이슈 없이 필요한 검증을 통과하면 조기 종료.
- 작업 완료 후 “○○을 메모리에 기억해둘까요?”라는 구체적 제안. 동의한 내용만 활성 기억에 추가.
- 기억 갱신 시 추가 기억까지 유지·수정·보관·재확인 필요로 재분류. 이전 버전 보존.
- 실제 검수 라운드와 통과/미완료/상한 도달 기록.

기본 검수는 변경 코드와 직접 영향을, 심층 검수는 관련 흐름과 실패 조건까지 살핍니다. 횟수 상한 도달은 통과가 아닙니다. 스킬에 의한 실행 절차이므로 모델의 누락을 원천 차단하는 강제 실행 엔진은 아닙니다. 독립 검수 에이전트가 없으면 자기 검수라는 점을 명시합니다.

## UI와 호환성

`harness_dashboard`는 MCP Apps HTML 리소스와 로컬 브라우저 URL을 제공합니다. **대화 안의 UI 표시는 앱/버전의 MCP Apps 지원에 따라 다르며 모든 Codex 화면에서 보장하지 않습니다.** 앱의 기본 설정 탭을 확장하지 않습니다.

대화 내 UI에서는 분석 요청을 현재 대화로 전송합니다. 호스트가 전송을 지원하지 않으면 복사할 요청을 표시합니다. 브라우저 UI에서는 버튼으로 요청을 저장한 뒤 표시된 요청을 복사하여 현재 프로젝트 대화에 보내세요. 브라우저가 독립적으로 AI를 실행하지 않습니다. 설정 저장·기억 제안 수락/거절은 브라우저에서도 바로 됩니다. 작업 후 상태 새로고침을 누르면 최신 정보를 볼 수 있습니다.

MCP 없이 화면만 실행할 수도 있습니다. 터미널을 유지하세요:

```text
python plugins/project-coding-harness/scripts/harness.py dashboard --project "프로젝트의 절대 경로"
```

출력된 `http://127.0.0.1:...` 주소를 브라우저에서 여세요. 서버는 로컬 주소에만 바인딩하고 무작위 접근 토큰과 동일 출처 검사를 사용합니다. 서버 프로세스 종료 시 URL도 만료됩니다. UI 연결 검증 범위는 [검증 문서](docs/VALIDATION.md)를 확인하세요.

## 기억 파일

각 프로젝트의 `.coding-harness/` 아래에만 기록합니다.

```text
.coding-harness/
  memory.md             # 실제 분석 및 동의받은 추가 기억 (정해진 Markdown 형식)
  state.json            # 설정, 대기 요청/제안, 검수 기록
  history/<revision>.md # 이전 기억 스냅샷
```

Markdown은 사람이 읽을 수 있으며, 메타데이터와 섹션 구분자는 도구가 관리합니다. 대기 제안은 활성 기억이 아닙니다. `archived` 기록은 보관만 하고 코드 방향성으로 쓰지 않습니다. `uncertain` 기록은 확인 전까지 규칙으로 쓰지 않습니다. 근거 파일 해시 및 Git HEAD 변경은 갱신 권장 신호이며, 변경이 없다는 표시가 전체 프로젝트의 최신성을 보증하지는 않습니다.

자동으로 매 작업마다 전체 기억을 덮어쓰지 않습니다. 작업 중에는 관련 코드로 사실을 재확인하고, 영구 갱신은 버튼 또는 명시적 요청으로 수행합니다. 아키텍처 변경처럼 오래 유용한 사실은 작업 완료 후 별도 동의를 받습니다. 명시적 갱신은 저장된 추가 기억의 근거 기반 재분류까지 포함합니다. 근거가 부족하면 즉시 지우지 않고 재확인 상태로 남깁니다.

프로젝트의 민감 정보가 포함될 수 있으므로 이 디렉터리를 공개 플러그인 저장소에 올리지 마세요. 팀과 공유할지 Git에서 제외할지는 프로젝트에서 결정하세요. 이 도구 자체는 네트워크로 프로젝트를 전송하지 않지만, 사용하는 AI 클라이언트가 소스를 읽고 처리하는 방식은 해당 클라이언트의 정책을 따릅니다.

## 업데이트와 제거

클론 폴더에서 `git pull` 후 `python install.py`를 다시 실행하고 앱을 재시작하세요. 설치 경로를 옮긴 경우도 다시 실행하세요. 이미 등록된 마켓플레이스 때문에 설치가 실패하면 `codex plugin marketplace upgrade personal` 후 다시 실행하세요. 현재 카탈로그 이름은 `.agents/plugins/marketplace.json`에 있습니다.

```text
codex plugin remove project-coding-harness@personal
codex mcp remove project-coding-harness
```

제거해도 프로젝트 기억은 삭제하지 않습니다.

## 개발·검증

```text
python -m unittest discover -s tests -v
```

외부 Python 패키지 없이 메모리 승인/갱신/복구, 프로젝트 격리, 검수 조기 종료·상한, MCP 및 로컬 UI API를 검증합니다. 도구 계약은 스킬의 `references/`에 있습니다.
